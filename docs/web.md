# The web app on plain React (phase C)

The web app was the Expo app exported for the browser (React Native Web): every hover, keyboard shortcut and table went through React Native's view model, the bundle carried React Native, and the design (the Notion-style prototype: one navigation hub on the left, breadcrumb bar, block timeline, properties pane on demand, multi-view accounts page, ⌘K) did not fit it. `apps/web` is the same product on the DOM.

## What is shared and what is not

- **Shared, imported as it is** from `packages/client/src` (alias `@m/...`): the API client, the session, the providers and hooks (`*-state.tsx`, `shell/data.tsx`, `shell/nav.tsx`, `agent-workspace.tsx`, …), every `*-core.ts` model, `shell/model.ts`, `shell/strings.ts` (every word the person reads), the domain package. A fix to a rule is made once and both apps get it.
- **Not shared:** anything that draws. The web draws with DOM elements and `apps/web/src/styles/app.css`; the phone keeps its React Native screens.
- **No React Native on the web.** The Vite build fails on any import of `react-native*`, `expo*`, `@expo/*`, `lucide-react-native` or `@copilotkit/react-native` (its `/headless` entry is aliased to `@copilotkit/react-core/v2/headless`, the same hooks). `apps/mobile/test/web-shared.test.ts` checks the shared modules stay free of them.
- **Platform files.** A mobile module `X` with a web version `apps/web/src/platform/X` is replaced by it in the web build (like Metro's `.web.tsx`). Only `platform-env.ts` (the few React Native environment bits: is this the web, the app coming to the foreground, the window width) needs one.

## Layout (the prototype)

- **Sidebar** (240, folds away for the simple view): space switcher (space ▾: switch space, settings, sign out), 搜索 ⌘K, 需要你 with its count, 项目 tree (营销总群 first; each project's accounts under it with their state dot), pages (进度汇报 with how many reports nobody has read, 账号与代理, 凭据, 项目资料), then 设置 and 新后台任务 at the bottom.
- **Main:** a breadcrumb bar (空间 / 项目 / 对话 ▾; on a page 空间 / 页面, or 空间 / 项目 / 页面 for the project's pages 进度汇报, 需要你 and 凭据, where 项目 leads back to the conversation) with light buttons: 进度汇报 with the unread count (the simple view only, whose sidebar is folded away), 账号, 详情, 更多 (平台管理 has only 更多). A page's own button pressed again (进度汇报, 账号) also leads back to the conversation, so a page always has a way out in the simple view on a computer (no sidebar, no tab bar). Then a banner slot of at most two rows (a system notice such as the worker being down, or the infrastructure stopping the project's runs, then the most urgent of the rest: the next step, a trial ending); the content; the composer. The infrastructure notice is one amber line for the project (`frame/strip.ts` `infraNoticeText`; the phone's `InfraBar.tsx` above the chat): a task whose runs keep failing (`runTrouble`, `packages/domain/src/standing.ts`) leads it with its title, how many runs in a row and why in the owner's words (otherwise only an incident of the system a run stands on, `systemIncidentKinds` proxy, desktop, network or model, open for `infraNoticeAfterMs`, 30 minutes, counts; a site's check, sign-in or rate limit, and a short outage, stay on the task's line and the account flag), else the parts that keep failing (the open incidents of live tasks) with since when and how many tasks are held, 「会自己重试」; it has no ✕ and goes by itself once runs work again; never in 需要你 and never a card per run.
- **The chat is the conversation only**: in time order, the person's messages and the replies with the cards that belong to them (a delegated task's card with its way to the task, tool cards, the credential guides, choices). No task report, no question or failure of a task, no 「后台正在做…」 line (`useChatSession({ conversationOnly: true })`); so a credential card's line after 保存 / 我弄好了 points to where the result goes (「结果写在进度汇报里；还要你处理的，会出现在「需要你」。」, `t.progress.web.guide`; the phone keeps 「结果会在这里告诉你」). In the 营销总群 the members' speech stays (`isGroupSpeech`: a project's request to the founder, a job taken, declined or done, the founder's reply for a project). The chat stays mounted under a page (进度汇报, 需要你, 平台管理, 账号…), so a reply keeps streaming, but what it shows is recorded as seen only while it is drawn and on the person's screen (`useChatSession`'s `inView`, false while a page covers it and, at phone width, while the properties pane or a panel does: they take the whole screen there; and `useOnScreen`: not while the browser tab is hidden or the phone app is in the background). 设置 has no 「汇报卡显示在聊天里」 any more; the phone app keeps its reports in the chat and its switch.
- **进度汇报** (a page of the frame like 需要你; sidebar 页面 first, the simple view's top-bar button, ⌘K, the phone's drawer and 更多 (a dot on ☰ and on 更多 while a report is unread), the pane's 全部汇报; `#progress` in the address: a reload keeps the page, the browser's Back closes it (a panel open over it, such as 打开任务's sheet, first: the page stays), closing it in the app goes back over the entry the app added, after a reload too (the entry's mark in `history.state`), so Back never meets a dead entry, and any other fragment, such as a password reset link's token, is left alone): 正在做 (the tasks running, queued or waiting to go on, one line each, 打开任务; only what runs moves, and while the worker has no heartbeat a line beside it says nothing will move and a run reads 后台停着 with where it stopped), then the project's reports newest first (every conversation's: a task started from a side chat reports here too, `ReportFeed(null)`), by day (今天 / 昨天 / 10月16日), each block led by its task's title (opens the task) with its label, time, summary (展开全文), links, 原文, 打开任务 and 更早 N 条 for one task's reports in a row; a stop report is the live need card while the task still waits for it, else the report with the receipt of what the person did. Tabs 全部 · 要你看 (failures, questions, reviews; empty, it points to 需要你 while that has items) · 对外动作 (an action on a site: a site and action, or a link) · 按任务. Older pages load on scroll. New reports are looked for every 5 s while the page is open and every 15 s otherwise (`check`: the project's newest five, the newest page only when they changed), so the count follows a side chat's reports too. What the selected tab lists is recorded as seen while the page is on screen (`useOnScreen`: the browser tab shown or the window focused; a report fetched while the page sits in a background tab stays new, for the phone's dots too) (`/api/chat-reports/read`, each report after its own conversation's last message, the person's or a reply, so the phone places it where it was seen), which clears the count; what only another filter tab of the page (要你看, 对外动作) lists stays new, and each filter tab shows how many new ones it holds (`tabUnread`). A report that was new during this visit keeps 新 on its block until the page closes (`freshReports`), so the person sees which one he was told about. One seen elsewhere (another window, the phone) reads as seen here once the newest reports the page checks change or the page reads them again. In the 营销总群 it is the hall's reports, the founder's included. Logic: `packages/client/src/shell/progress/progress-core.ts` (tests `apps/mobile/test/shell-progress.test.ts`), state `progress-state.tsx`, page `apps/web/src/progress/ProgressPage.tsx`.
- **Properties pane** (340; docked in the pro view, shown in the simple view once 详情 is pressed, an account is picked or a chat card's 查看 points to one of its sections): the conversation's 此刻 (`summaryLine`: 「N 个号在跑」 only for a run, 「N 件排队中」 for a queued task, 「N 件等下一轮」 for a wait, a retry or a schedule, and while the worker has no heartbeat and anything is to move 「后台停着，不会推进」 first and nothing as running: `ShellData.stalled`, the same source as 进度汇报's line; the members' 正在做, the sidebar's dots and the phone chat's status lines follow it, and so does every run's phase in ShellData's entries (`stalledPhase`): it reads 「后台停着」 (grey pill, grey account light, the line 「后台停着，不会推进」) wherever it shows, the pane's 任务 rows, 账号与代理's 此刻 column, the phone's account rows, ⌘K, the task cards, 进度汇报's 正在做 (where it stopped, 「停在第 2/5 步 · …」) and the task panel (停在这一步 instead of 现在在做)), 需要你, 账号 (in the 营销总群 the founder apart, under 营销总群 · 创始人, the rest 未分配账号: she is never counted 未分配, nor in ⌘K's 「n 个未分配」), 最近汇报 (with 全部汇报 to 进度汇报), 项目资料, or the account picked anywhere (a row, a face), its place named as 账号与代理 names it (`accountPlace`: 「这个号在「营销总群 · 创始人」」 and 「切到 营销总群 · 创始人」 for the founder seen from another project, never 未分配; an exit's group and note too, `placeOf`). Wherever a report shows as a line (the pane's 汇报, the task panel's 本任务汇报, an account's 最近汇报, the phone's rail), an action report without the item's own address reads 「未确认：没有这条内容自己的链接」 under it, as its card does (`unconfirmedLine`; owner: 「这个任务说是完成了，我连链接都没看到」).
- **Panels:** one sheet at a time from the right (task, job, account editor, settings…), Escape closes; over 进度汇报 or 平台管理 the browser's Back closes the sheet before the page.
- **Phone width (< 860):** the sidebar becomes a drawer behind ☰; a tab bar at the bottom (对话 · 需要你 · 账号 · 更多, which holds 进度汇报); the pane and panels take the whole screen.
- **Pro and simple views** are the sidebar and pane shown or folded (`view-mode.ts`, the same switch the phone app has).

## Build and serve

`apps/web` is its own pnpm workspace (`apps/web/pnpm-workspace.yaml`, its own lockfile resolved by pnpm 11 under the same release-age policy: adding it to the root workspace would move the server's resolved versions). `cd apps/web && pnpm install --frozen-lockfile`, then `VITE_API_URL=<public API> npx vite build` (`VITE_BUILD` = the commit for the version line), output `apps/web/dist`. An `apps/web/index-extra.html` beside `index.html`, or the file `WEB_INDEX_EXTRA=<file>` names (v1.7.1), goes into the page source just before `</body>`, for what a reader of the raw page must see without scripts (a directory's badge); the Docker build takes `WEB_INDEX_EXTRA` as a build argument of the same name.

`apps/web/dist` is what the site serves. The deploy script builds it for the root and stops before swapping anything if the build fails (the site depends on it). It still builds the Expo export into `apps/mobile/dist/web`. Paths the app reads or writes go through `src/base.ts` (the base is `/`).
